# REGEX_DOCUMENTATION.md — AegisLex

Complete reference of every regular expression and field validator currently
in the project, generated by reading the actual source (not assumed from
memory). Source of truth for the custom regex constants:
`src/app/shared/auth-components/auth-validators.ts`.

This file documents two categories:
1. **Custom regex** defined and used in this codebase.
2. **Built-in Angular validators** (`Validators.required`, `.minLength`,
   `.maxLength`, `.email`, `.requiredTrue`) used on fields that have **no**
   project-authored regex — included so every validated field in the project
   is covered, per the audit requirement to document ALL validated fields.

---

## 1. Email — `EMAIL_REGEX`

**Field name:** Email Address
**Used by:** `emailValidator` (Register, Login, Forgot Password)
**File:** `auth-validators.ts`

```
/^[A-Za-z0-9._%+-]+@[A-Za-z0-9]([A-Za-z0-9-]*[A-Za-z0-9])?(\.[A-Za-z0-9]([A-Za-z0-9-]*[A-Za-z0-9])?)*\.[A-Za-z]{2,}$/
```

**Purpose:** Validates standard email address structure: local-part, `@`,
one or more domain labels separated by dots, and a final alphabetic TLD of
2+ characters.

**Accepted examples:**
- `user@example.com`
- `user.name@example.co.uk`
- `ahmed.al-mansouri@corp.legal`
- `info@aegislex.ai`

**Rejected examples:**
- `ziadgmail.com` — missing `@`
- `user@domain..com` — consecutive dots in domain
- `user@-domain.com` — domain label starts with a hyphen
- `user@domain-.com` — domain label ends with a hyphen
- `user@domain` — no dot / TLD
- `user @example.com` — contains a space

**Validator logic (`emailValidator`):**
1. Trim the value.
2. Whitespace-only input → `required` error.
3. Trimmed length > 254 → `emailTooLong` error.
4. Fails `EMAIL_REGEX` → `invalidEmail` error (message resolved by
   `getEmailErrorHint()`, see §9).

**Error messages:**
| Key | Message |
|---|---|
| `required` | Email is required. |
| `emailTooLong` | Email cannot exceed 254 characters. |
| `invalidEmail` | Context-specific hint from `getEmailErrorHint()`. |

**Also referenced directly (not just via validator):** `login.component.ts`
imports `EMAIL_REGEX` itself to compute `loginDisabled` (disables the Sign In
button until the typed email matches the pattern).

## 5. Password — `passwordValidator` (registration / reset)

**Field name:** Password / New Password
**Used by:** Register (Step 2), Reset Password
**File:** `auth-validators.ts`
**Regexes (all four checked simultaneously against the trimmed value):**

| Constant | Pattern | Checks for |
|---|---|---|
| `PASSWORD_UPPERCASE_REGEX` | `/[A-Z]/` | at least one A–Z |
| `PASSWORD_LOWERCASE_REGEX` | `/[a-z]/` | at least one a–z |
| `PASSWORD_NUMBER_REGEX` | `/\d/` | at least one digit |
| `PASSWORD_SPECIAL_REGEX` | `/[^\w\s]/` | at least one char that is not a word character and not whitespace |

**Purpose:** Enforces an 8–64 character password containing upper case,
lower case, a digit, and a special character.

**Special characters matched by `[^\w\s]`:**
`! @ # $ % ^ & * ( ) - + = [ ] { } | ; ' " , . < > / ?` — anything outside
`[A-Za-z0-9_]` and outside whitespace. Note: `_` is **not** treated as
special, because `\w` includes underscore.

**Accepted examples:** `Secure#Pass1`, `LegalA1@Dubai`
**Rejected examples:**
- `password` — no uppercase, no digit, no special char
- `SHORT1!` — only 7 characters (< 8)
- `NOLOWER1!` — has uppercase/digit/special but no lowercase

**Error messages:**
| Key | Message |
|---|---|
| `required` | Password is required. |
| `pwTooShort` | Password must contain at least 8 characters. |
| `pwTooLong` | Password cannot exceed 64 characters. |
| `pwNoUpper` | Password must contain at least one uppercase letter. |
| `pwNoLower` | Password must contain at least one lowercase letter. |
| `pwNoNumber` | Password must contain at least one number. |
| `pwNoSpecial` | Password must contain at least one special character. |

All applicable errors are returned together (not one-at-a-time), so the UI
can show every unmet requirement at once.

## 6. Confirm Password — `passwordMatchValidator`

**Field name:** Confirm Password
**Used by:** Register (Step 2), Reset Password
**File:** `auth-validators.ts`
**Regex:** None — equality comparison of the two trimmed values. This is a
form-group-level validator (sets the error on the group, not the control).

**Purpose:** Ensures `password` and `confirmPassword` match.
**Edge case:** Returns `null` (no error) if either field is still empty,
so the mismatch message doesn't appear prematurely while the user is still
typing the first field.

**Error messages:**
| Key | Message |
|---|---|
| `required` | Confirm password is required. |
| `passwordMismatch` | Passwords do not match. |

## 7. OTP — `OTP_FULL_REGEX`

**Field name:** One-Time Password (6-digit code)
**Used by:** Verify OTP page (`verify-otp.component.ts`)
**File:** `auth-validators.ts`

```
/^\d{6}$/
```

**Purpose:** Confirms the assembled 6-digit code is exactly 6 numeric
digits before auto-submitting.

**Accepted examples:** `123456`, `000000`
**Rejected examples:** `12345` (5 digits), `1234567` (7 digits), `12345a` (contains a letter)

**Where it's actually used:** `verify-otp.component.ts` calls
`OTP_FULL_REGEX.test(code)` after each digit is typed and after paste, to
decide whether to auto-submit. Non-digit characters are stripped from
keystrokes/paste with `/\D/g` before this check ever runs, so the regex
itself never needs to reject letters in practice — it's a final safety
check on the assembled string.

**Error messages (component-level, not from the regex itself):**
| Condition | Message |
|---|---|
| Empty | OTP is required. |
| Fails the 6-digit check | OTP must contain exactly 6 digits. |
| Server rejects (< 3 attempts) | Invalid OTP. |
| Server rejects (≥ 3 attempts) | Maximum attempts exceeded. |

**Related, currently unused exports (documented for completeness):**
- `OTP_DIGIT_REGEX = /^[0-9]$/` — written for validating a single OTP box,
  but the component strips non-digits manually instead; this constant is
  not currently imported anywhere. Left in place since removing an exported
  constant is outside the scope of this audit and carries no behavioral risk.
- `otpValidator()` — a full `AbstractControl` validator function that wraps
  `OTP_FULL_REGEX`, but no form in the project currently uses a
  `FormControl` for OTP entry (the page uses a manual signal-backed digit
  array instead), so this function is not wired to any template. Not
  modified, per the "don't touch what isn't confirmed broken" rule — this
  is dead code, not a defect.

## 8. Whitespace-only detector — `WHITESPACE_ONLY_REGEX`

```
/^\s+$/
```

**Purpose:** Detects a string that contains only spaces/tabs (as opposed to
a truly empty string), so "typed spaces and nothing else" can be reported
as a `required` error rather than silently passing. Exported from
`auth-validators.ts` "for legacy compat," but not currently imported by any
component — each validator (`emailValidator`, `firstNameValidator`, etc.)
re-implements this same whitespace check inline rather than calling this
constant. Documented for completeness; not modified.

## 9. Email error-hint helper — `getEmailErrorHint()`

Not a regex itself, but directly downstream of `EMAIL_REGEX` failing — included
because it determines the user-facing message.

| Input | Output |
|---|---|
| `ziadgmail.com` | Missing @ symbol. |
| `ziad@` | Missing domain after @. |
| `ziad@gmail` | Missing dot before TLD (e.g. gmail.com). |
| `ziad@@gmail.com` | Multiple @ symbols detected. |
| `ziad..test@gmail.com` | Consecutive dots detected. |
| anything else still invalid | Please enter a valid email address. |

**Used by:** Login, Register, Forgot Password.

## 11. Profile — First Name / Last Name (`profile.component.ts`)

**Field names:** First Name, Last Name (Profile edit page)
**Regex:** None. Uses Angular's built-in `Validators.required` +
`Validators.minLength(2)`.

**Note on consistency (documentation only, not changed):** Registration's
`firstNameValidator`/`lastNameValidator` require **3+** characters, while
the Profile edit form's built-in `minLength(2)` only requires **2+**
characters for the same logical field. This is a pre-existing rule
difference between the two forms, not a regex defect — registration and
profile-editing are separate forms with separate validators, and the audit's
"DO NOT GUESS / do not rewrite working validators without proven defect"
rule means this was left as-is. Flagged here purely for visibility in case
product wants the two forms aligned in a future, deliberate pass.

**Error messages (generic, from `fieldError()`):**
| Key | Message |
|---|---|
| `required` | Required |
| `minlength` | Min 2 chars |

## 13. Profile — Password Change (`profile.component.ts`)

**Field names:** Current Password, New Password, Confirm New Password
**Regex:** None.
- `currentPassword`: `Validators.required` only.
- `newPassword`: `Validators.required` + `Validators.minLength(8)` (no
  uppercase/lowercase/digit/special-character requirement — simpler than the
  registration password rule).
- `confirmPassword`: `Validators.required` only; match check (`newPassword
  !== confirmPassword`) is done in component code (`changePassword()`) via a
  toast message, not a form-level validator.

**Error messages:**
